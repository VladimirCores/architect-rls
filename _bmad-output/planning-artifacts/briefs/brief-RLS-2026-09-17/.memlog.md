- (event) User described RLS simulator trainer product: boid flock simulation for operator training, desktop client-server, 3 modes (simulation/training/exam), map system with polygon regions, RLS radius visualization, role-based access (operator/admin), timed exam with replay, feature flags for RLS/boid CRUD.
- (event) Discovery answers: 1) Context: object security, end users = private security + military academy students. 2) Boid statuses extensible, default = 'unknown'. 3) Real-time no acceleration, speed 10-300 km/h, distances 1-100km, RLS radius scales with params, boids move randomly/straight/arc/toward target. 4) Exam records full session: operator events, boid coordinates, map, statuses for replay. 5) Client-server local, same API contracts for future web version. 6) Feature flags are boolean. 7) Custom maps via .mbiles vector tiles.
- (event) Discovery continued: 1) Operator determines danger by experience/intuition based on speed+trajectory+combination. 2) Exam pass/fail handled by external system/person; simulator produces reports with percentages. 3) Replay includes both boid movement and operator actions. 4) Future features: analytics/statistics, reports, export, settings, integrations.
- (event) Discovery continued: Feature flags for reports, statistics, map upload, settings, exam recording upload. Simulation settings configurable; guard objects, RLS, boid params are fixed reference data. Multiple RLS and multiple guard objects on map, admin/user with permissions can change positions. Boid entering guard polygon disappears, impact shown on object. Boid hitting RLS disables it. No RLS remaining = session failure.
- (event) Discovery continued: Boids, RLS, guard objects are CRUD-able (admin/user with permissions). Guard objects placed on specific map areas. Multiple maps available in program folder, selectable. Simulation speed is fixed (not configurable), only adjustable during replay.
- (event) Brief drafted. Ready for review.
