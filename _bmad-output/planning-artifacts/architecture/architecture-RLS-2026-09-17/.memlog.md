- (decision) Paradigm: Multiplatform API-first modular monolith. Desktop (Linux, Windows) is the primary client; same API contracts serve future web version. Single deployable unit with clear module boundaries. API contract is the source of truth; clients are consumers.
- (decision) Added Reports module to the architecture: individual user reports and cross-user reports. Reports module reads from Event Store and Reference Data to generate exam results, session summaries, and aggregated statistics.
- (decision) Rendering decision: Flutter Custom Painter (Canvas 2D) for the map view. Single canvas layer renders all map elements: polygons (guard objects), RLS circles (detection radius), boids with trails, and status markers. Rationale: need to draw polygons, circles, and moving objects together; hit-testing via coordinate check on the canvas.
- (decision) Interaction model: Event-driven with client-side state machine for actions (idle, progress, complete, failed). Visual status indicators as colored circles near boids that fade after timeout on terminal states. Confirmation pattern (second click) for destructive actions: red button with 'confirm' text for delete, yellow for update.
- (decision) Data flow optimization: Server-authoritative. REST for status changes, WebSocket for coordinate updates. Inactive/stopped boids not sent via WebSocket; client retains them locally and renders on map.
- (decision) Simulation Engine reads Reference Data directly (read-only dependency, no circular dep). Session Manager owns session state (map, active RLS, active boids, timer, exam recording). Separation of concerns: Simulation Engine runs the simulation, Session Manager tracks the session lifecycle and persists state.
- (decision) Session lifecycle: Server initiates exam/training completion (authoritative timing). Session Manager saves in real-time (not after session ends) - writes events to Event Store as they happen, not batch at end. This ensures no data loss if the session is interrupted.
- (decision) Maps: Stored on server filesystem. Client requests list of available maps (refresh button). Users with map-upload feature can upload new .mbtiles files which immediately overwrite the current map. No versioning - last upload wins.
- (decision) Reports module: Data from Event Store + session/simulation parameters (time spent, results, boid counts, detection times by status, etc.). Formats: JSON primary, PDF future. Access: users see own reports, admin/feature-enabled users see all reports.
