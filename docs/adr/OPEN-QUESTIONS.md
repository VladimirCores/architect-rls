## Открытые вопросы

1. **`SUPPORTED_REGIONS`** — **решено:** статический список отменён. Доступность = сканирование директории карт при старте (`MapProvider`, `infrastructure/`); метаданные — sidecar `regions.json` (fallback — имя файла); выбор — только `MAP_TILES` в `.env`. См. ADR-0011.
2. **argon2id** — **решено:** fallback не нужен; формат argon самонесущий (m/t/p зашиты в хэш), смена параметров не ломает старые хэши. Параметры фиксируются один раз после замера на слабейшей целевой машине (бюджет ≤ ~300 мс). `64 MiB / t3 / p1` — если влезает в бюджет.
3. **planetiler** — **решено:** параметры — операционные, живут в README/CI: версия пинится (`PLANETILER_VERSION`); Москва+область — heap `-Xmx6g`, threads=`nproc`, диск ≈ 2× выхода. **Dev-уточнение:** dev-регионы маленькие — 3–4 уровня зума, слои только до зданий (≈1–2 см на экране), рельеф/ландшафт не нужны. См. ADR-0012.
4. **GitLab CI cache key** для MBTiles — **решено:** `mbtiles-{region}-{planetiler_version}-{pbf_sha256}` (`source_hash` = sha256 загруженного `.osm.pbf`). См. ADR-0012.
5. **`_migrations`** — **решено:** `status` — enum `applied|failed`; отдельного `dirty` нет — прерванная миграция = строка `failed`, блокирует последующие до ручного решения; `checksum` (hash SQL) для детекта дрейфа схемы. См. ADR-0006.
6. **`POST /event`** — **решено:** `type` — enum в коде (как базовые features, ADR-0004): тип растёт с версиями, админской настройкой не является; БД-справочник добавляет запрос и синхронизацию. Rate-limit: fixed-window по uid, дефолт 100/с, конфигурируемый на сервере (ADR-0008).
7. **Retention-политика** для `events` — **решено:** desktop — без автоудаления, ручная очистка (объём мал); сервер — `EVENTS_RETENTION_DAYS` (дефолт **365**), nightly GC. `.rlsrec` — на сервере вместе с событиями, локально вручную.
8. **Contract-тесты** — **решено:** Schemathesis на **каждый MR** (contract — gate; nightly поздно); baseline — `swagger/`; джоба поднимает backend в local-режиме на тестовой БД, фейл блокирует merge.
9. **`/admin/users/:id`** — **решено:** `/profile` + `created_at`, `disabled`, сырые назначенные features (до объединения с базовыми). Доп. поля (last_login и т.п.) — по необходимости из аналитики, в роут не вводятся.
10. **CORS** — **решено:** `@hono/cors` только в dev, включается в фабрике middleware по `DEPLOYMENT_TYPE`; под reverse proxy в prod CORS не нужен (same-origin), заголовки при необходимости — на прокси. См. ADR-0015.
11. **`LICENSES.md`** — **решено:** Node/Bun — `license-checker-rseidelsohn`; Flutter — `flutter_oss_licenses`. CI-джоба генерирует `LICENSES.md` (машинно, не вручную) и **фейлит на запрещённых лицензиях**: **GPL / AGPL / SSPL**. Init-проверка — валидация свежести (файл существует + версии совпадают).
12. **Три БД на desktop** — **решено:** разделение подтверждено и локально: отдельные `app.db` и `analytics.db` в одном каталоге данных, реплей-файлы — `recordings/` вне БД. См. ADR-0011.
13. **`better-sqlite3` + Bun** — **решено:** `better-sqlite3` удалён из стека; локальный драйвер — встроенный `bun:sqlite` (через `drizzle-orm/bun-sqlite`). Причина: нативный V8-аддон не грузится в Bun. Прототип на старте сохраняется, но проверяет драйвер/миграции/WAL, а не сборку модуля. См. ADR-0001.
14. **`DEPLOYMENT_TYPE`** — **решено:** полный список ветвлений — БД, провайдер/источник карт, EventBus, логгер (ADR-0008) + CORS, bind-адрес, миграции (на старте / CI-шаг), rate-limit, детализация ошибок. **Правило:** `if DEPLOYMENT_TYPE` только в `infrastructure/` (фабрика), никогда в `domain/application/controllers`. См. ADR-0008.
15. **`/actions/simulation/*`** — **решено:** единый ответ на все четыре — `{session_id, status: running|paused|completed, tick}`; `start` дополнительно эхом возвращает параметры сессии. Итоги/статистика — в аналитику и GET-эндпоинты, в ack не вливаются.
16. **Пометка boid** — **решено:** отдельный `POST /actions/boids/mark` в семействе `/actions/*`. CRUD `/boids` — справочник; пометка — действие оператора над живым инстансом (ADR-0005, событие `boid.marked` в ADR-0014). `ts` — в tick симуляции, серверное время — fallback/валидация. Перемена решения = новое событие (last-write-wins).
17. **`GET /logs`** — **решено:** роут читает **хвост активного файла лога** (список-формат с пагинацией: total строк, offset). Отдельного хранилища логов нет (ADR-0013); на сервере — то же с ротацией.
18. **Воспроизведение сессии** — **решено (направление, post-MVP):** записываются **координаты** автономным файлом записи `.rlsrec`, не события. Инварианты:
      - Самодостаточный файл: header (session_id, параметры симуляции + seed, `map_version`/`style_version`) + таблица тайлов (dedup по z/x/y + hash) + кадры (Float32 геокоординаты, дельта + zstd).
      - Координаты — географические, со сверкой по карте; кадры — зеркало WS-пейлоада (единый сериализатор).
      - Analytics DB хранит только индекс сессий (метаданные + путь к файлу); события — как сейчас (индекс поверх кадров).
      - Схема `events` при проектировании не должна закрывать будущие `session_frames`/`.rlsrec`.
19. **Парадигма и модули** — **решено:** Multiplatform API-first modular monolith; 8 модулей с жёстким направлением зависимостей. См. ADR-0017.
20. **Рендеринг карты** — **решено:** единый слой Canvas 2D (Flutter Custom Painter) для полигонов, РЛС, boids, шлейфов, статусов; hit-testing — координатная проверка. См. ADR-0018.
21. **Модель взаимодействия** — **решено:** event-driven с клиентской машиной состояний `idle/progress/complete/failed`; паттерн «второй клик» для деструктивных действий. См. ADR-0019.
22. **Поток данных** — **решено:** server-authoritative; REST для статусов, WebSocket для координат; неактивные boids не передаются по WS (клиент хранит локально). См. ADR-0020.
23. **Жизненный цикл сессии** — **решено:** завершение инициирует сервер; Session Manager сохраняет в реальном времени. См. ADR-0021.
24. **Хранение карт** — **решено:** файловая система сервера, перезапись без версионирования, клиент запрашивает список. См. ADR-0022.
25. **Отчёты** — **решено:** данные из Event Store + параметров сессии; JSON основной, PDF будущее; пользователь видит свои, admin/особенность — все. См. ADR-0023.
26. **Swagger multi-file** — **решено:** домен-ориентированная структура — `swagger/<domain>/paths.yaml` + `entities.yaml`, общие схемы (Problem, ProblemResponse, OkResponse) в корневом `swagger/entities.yaml` (DRY); `$ref` — относительные `file.yaml#/pointer`, пути из корня — JSON Pointer (`/` → `~1`); Swagger UI — через корневой `docker-compose.yml` (образ `swaggerapi/swagger-ui`, порт 9989, `npm run swagger:ui`). См. ADR-0024.
27. **Линтер TS** — **решено:** Biome 2.x — единый линтер и форматтер для всех Bun-workspace пакетов (`backend`, `swagger`, root); конфиг `biome.json` в корне; скрипты `lint`/`lint:fix`/`format`. См. ADR-0025.
28. **Генерация API-кода (Hono-роуты + Zod)** — **решено:** `orval` (`client: 'hono'`) из бандла `swagger/dist/openapi.json` (`redocly bundle`) → `backend/src/generated/` (endpoints/, handlers/, schemas/). Бизнес-логика — вручную в `backend/src/controllers/`; стабы-обработчики вызывают контроллеры (smart-стратегия Orval сохраняет вызов). Запуск: `bun run generate:api` (корень). Заменяет прежний `@hono/zod-openapi` (spec ← код). См. ADR-0005.
