# ADR-0019: Модель взаимодействия оператора

**Дата:** 2026-09-17
**Статус:** Accepted
**Теги:** frontend, interaction

---

## Контекст

Оператор взаимодействует с boids на карте: hover для параметров, ЛКМ для пометки «опасный», ПКМ для меню статусов. Действия отправляются на сервер через REST (event-driven). Нужно определить, как клиент отражает состояние действий и как подтверждаются деструктивные операции.

## Решение

- **Event-driven** с клиентской машиной состояний для каждого действия: `idle → progress → complete | failed`.
  - `complete` / `failed` — конечные состояния.
  - В `failed` — показывается сообщение об ошибке.
- **Визуализация статуса действия:** цветной кружок рядом с boid; на конечных состояниях (`complete`/`failed`) кружок пропадает через заданное время.
- **Подтверждение деструктивных действий — паттерн «второй клик»:**
  - Удаление: кнопка заменяется на красную с текстом «подтвердить».
  - Обновление: кнопка заменяется на жёлтую с подтверждением.
- **Статусы boids настраиваются отдельно** (admin): статус, цвет пометки.

## Следствия

**Положительные:**
- ✅ Пользователь всегда знает, в каком состоянии действие.
- ✅ Деструктивные операции защищены от случайного клика.

**Отрицательные / риски:**
- ⚠️ Машина состояний требует аккуратной обработки гонок (быстрый повторный клик).
