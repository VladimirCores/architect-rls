# ADR-0008: Режимы развёртывания backend

**Дата:** 2026-09-17
**Статус:** Accepted
**Теги:** backend, infra

---

## Контекст

Backend должен работать и как локальный процесс на десктопе (SQLite), и как сервер (Postgres, в будущем — k8s).

## Решение

- **Переключатель:** ENV `DEPLOYMENT_TYPE={local|web}` (приоритет ENV над вшитой константой — см. ADR-0002). Фабрика: при неизвестном значении — ошибка запуска (fail-fast).
- **Фабрика зависимостей:** драйвер БД, провайдер карт, EventBus, логгер — выбираются по `DEPLOYMENT_TYPE`.
- **Локально:** одна сборка Bun (скомпилированный бинарник), SQLite, in-process pub/sub, файловые логи.
- **Сервер:** тот же код, Postgres, внешний Redis pub/sub (при RPS-триггере), логи в файл (пока).

### Полный перечень ветвлений по `DEPLOYMENT_TYPE`

1. Драйвер БД: `bun:sqlite` / Postgres.
2. Провайдер карт и источник тайлов (MBTiles-файл / кэш-копия на сервере).
3. EventBus: InProcess / Redis.
4. Логгер и его писатели (файл).
5. CORS: только в dev (см. ADR-0015).
6. Bind-адрес: localhost на десктопе vs внешний порт за reverse proxy.
7. Миграции: на старте на десктопе vs отдельный CI-шаг на сервере (ADR-0006).
8. Rate-limit: локально включён (burst 20, window 1 мин) для защиты от brute-force; на сервере — включён с более жёсткими лимитами (`POST /event` и др.).
9. Детализация ошибок: dev — подробно, prod — `application/problem+json` без внутренностей.

**Правило:** `if DEPLOYMENT_TYPE` — только в `infrastructure/` (фабрика); в `domain/`, `application/` и `controllers/` ветвлений нет.

## Следствия

**Положительные:**
- ✅ Один кодовый базис.
- ✅ Переиспользование на сервере без форка.

**Отрицательные / риски:**
- ⚠️ Различия (SQLite vs Postgres) локализованы в репозиториях; часть запросов может потребовать двух реализаций.
