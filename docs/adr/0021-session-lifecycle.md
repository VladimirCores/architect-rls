# ADR-0021: Жизненный цикл сессии

**Дата:** 2026-09-17
**Статус:** Accepted
**Теги:** backend, session, simulation

---

## Контекст

Три режима — симуляция (бесконечная), тренировка (с таймером, стоп/сброс), экзамен (с таймером, запись, отчёт). Нужно определить, кто инициирует завершение сессии и когда сохраняется запись.

## Решение

- **Session Manager владеет состоянием сессии** (карта, активные РЛС, boids, таймер, запись экзамена). Simulation Engine отделён и выполняет расчёт движения.
- **Завершение экзамена и тренировки инициирует сервер** (authoritative timing). В реальности время может длиться долго, пока сервер или «управляющий» не решит, что закончено.
  - Симуляция — бесконечна, завершает её оператор/сервер вручную.
  - Тренировка/экзамен — таймер на сервере; истекло время / уничтожены все РЛС = завершение.
- **Session Manager сохраняет в реальном времени**, не по окончании сессии.
  - События пишутся в Event Store по мере их возникновения.
  - Это исключает потерю данных при обрыве/крахе сессии.
- **Завершение сессии** → запись события `session.completed` → генерация отчёта (экзамен).

## Следствия

**Положительные:**
- ✅ Нет потери данных при прерывании сессии.
- ✅ Сервер — единый источник истины по времени.

**Отрицательные / риски:**
- ⚠️ Непрерывная запись событий — рост объёма данных (решается retention-политикой, ADR-0011).
